# Passerelle

## Requirements

* Docker
* Ruby (any recent version, only the standard library is used to run `bin/dx`)

The project runs inside Docker containers (the app, PostgreSQL & Redis),
managed by the `bin/dx` command.

## Setup

Download the project and run:

```shell
$ bin/dx build            # Build the app image from Dockerfile.dev
$ bin/dx start --setup    # Start containers & setup the project for the first time
```

To get more options about setup steps, you can try:

```shell
$ bin/dx setup --help
```

Default ports (3000, 1080, 5432 & 6379) may clash with other local services.
They can be overridden in `.docker/docker-compose.local.env`, generated by `bin/dx build`.

## Running the app

To start the application, just run:

```shell
$ bin/dx dev
```

To get more options about running processes, you can try:

```shell
$ bin/dx dev --help
```

## Tests and continuous integration

To run the full CI suite, run:

```shell
$ bin/dx ci
```

To get more options about how to run tests and CI, run:

```shell
$ bin/dx ci --help
```

## Managing containers

```shell
$ bin/dx start            # Start all containers
$ bin/dx stop             # Stop all containers
$ bin/dx sh               # Open a Bash shell in the app container
$ bin/dx rails c          # Start a Rails console
$ bin/dx exec [command]   # Run any command in the app container
```

To get the full list of commands, you can try:

```shell
$ bin/dx --help
```

## Additional configuration

Depending on runtime, we might use environnement variables to define custom configuration.

In production, environnement variables must be defined through the cloud provider API.  

In development & test, environnement variables may be defined in `.env` files.  
Learn more about `.env` files at https://github.com/bkeepers/dotenv

## Subdomains

Some part of the application, use subdomains, such as `api.`.

In development, uses the domain [passerelle-fiscale.localhost](http://passerelle-fiscale.localhost:3000) to navigate between subdomains out of the box.
